## What went well
- **The correctness reviewers paid off** (top recommendation of the 2026-10-28 retro): 6 WARNINGs
  were found and fixed inside the run, including one doc rejecting all docs, a missing key shown as a 502,
  O(n²) tokenizing on the event loop, patchless files dropped, and a client refetch error hiding a good brief. The
  later `/pr-self-review` then found **0 backend findings** and 0 CRITICAL overall.
- **No AC mismatches** from either test-writer (73 unit + 18 integration tests): spec-first tests went green
  on the code as written, so Step 4 had nothing to do.
- **Lanes never collided:** 11 implementer tasks with disjoint owned paths and no write-hook denials.
  The orchestrator granted one ownership exception explicitly (T6 removing two `brief.json` keys after T2 finished).
- **Cache hit 85%**, in line with earlier runs (86%, 80%).
- The architecture gate PASSed first time (0 critical / 0 high); arch:check stayed clean throughout.

## What was hard / wasteful
- **Test phase dominates (19.7 min).** Splitting server tests into unit ‖ integration (the 2026-10-28
  recommendation) ran both in parallel, but each one alone took longer than the old single writer (824 s).
  T11 (unit only, no Docker) produced **104k output tokens**, the most of any agent, for 73 tests in 4 files.
  Its cost is test generation volume, not Docker.
- **max-parallel 2 was the ceiling.** Parallelism was 1.58x out of a possible 2.0x, and tasks queued behind it.
  T5 (seed) was ready at 1.5 min but started at 12.7 min. T3/T5/T8 and T5/T6/T10 were ready together three times.
- **A fix created the next finding.** Fix-loop iteration 2 existed only because iteration 1's
  `withPatchlessFiles` merged *all* missing `pr_files` rows (stale after force-push). The fixer brief named
  D5 but did not ask the fixer to consider stale data.
- **AC-66 marked partial by plan-verifier** (+4 min, 2 agents). The plan's T6 acceptance listed "refresh
  placement in banner vs block". The implementer tested only that the button existed and still reported AC-66 as closed.
- **Plan referenced a file that does not exist:** `e2e/docs/flow-contract.md` (T13, gotchas). The implementer
  fell back to `e2e/lib/assert.ts`.
- **Flaky `skills.it.test.ts`** made the orchestrator and plan-verifier run the full integration suite twice (~2–3 min).
- **Duplicated context:** every implementer opened the 560-line plan (about 28k tokens, beyond one Read page) even
  though the brief already carried its task block verbatim. Repeated about 15 times, this is cached input, so it costs time more than money.

## Missed — caught only after the run
- **T14 (real model):** every real Generate call returned 502 behind a generic "model call failed, try again".
  - The causes were environmental: OpenAI 429 (no credits), then an OpenRouter `:batch` model (404).
  - The masking is a **spec gap**: no AC tells the user the provider's error *category*. Mocks never exercise it.
  - The model picker offers `:batch` models that cannot work.
  - A `.min(1)` → `minLength` in the strict schema was fixed as a precaution, but it was never confirmed as a cause.
- **`/pr-self-review`:** 1 WARNING. `OverviewTab.test.tsx:82` uses a fixed 50 ms sleep before absence assertions. The
  client correctness reviewer covered "tests that assert the wrong element" but not async waits.

## Recommendations (actionable)
1. **`/run-plan` default `max-parallel` 2 → 3** for the implementation phase, when the plan lists ≥ 3 disjoint
   ready tasks. Expected: about 5 min saved here (T5 queued 11 min), and parallelism toward 2.2x. Reviewers and fixers stay at 2.
2. **`implementation-planner`: split test-writer tasks per test file, not just unit vs integration**, when one
   task owns more than ~25 ACs, for example T11a contracts+helpers and T11b service. Expected: the test phase drops from about 20 to about 11 min,
   because output volume is the bottleneck.
3. **`run-plan` Step 2 fix brief:** add "state what new failure mode your fix could introduce (stale data,
   concurrency, error mapping) and guard it". Expected: avoids the fix-of-a-fix iteration (iteration 2 here).
4. **`implementer` UI acceptance:** require one assertion per *observable* clause of each AC it closes, quoted in the
   test title, before reporting `Closes: AC-N`. Expected: no "partial" verdicts like AC-66.
5. **`spec-creator` (LLM features):** add a mandatory AC for the user-visible error *category* on provider failure
   (quota 429 / auth 401 / model unavailable 404 / timeout), without provider text. Expected: T14-style failures
   are diagnosable from the UI, not only the server log.
6. **`implementation-planner`:** check that every path cited in gotchas exists (`ls`) before writing the plan.
   Expected: no dangling `flow-contract.md`-style references.
7. **Correctness reviewer focus (client):** add "fixed sleeps / `setTimeout` used as waits in tests". Expected: catches
   the one WARNING that reached `/pr-self-review`.
8. **Brief tweak (orchestrator):** tell implementers "your task block is above; read only the plan sections named
   in it (Decisions Dn), not the whole plan". Expected: fewer ~28k-token plan reads.
